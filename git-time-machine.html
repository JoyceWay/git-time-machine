从前，有个见习女巫，名叫女巫，学做网站。

她的电脑里有一个文件夹，叫"网站最终版"。还有"网站最终版2"。"网站最终版真的最终"。以及"网站最终版真的最终再也不改了"。

有一天，她改崩了。想回到今天早上。回不去。

她哭了。然后她在旧货市场，淘到了一台二手时光机。附说明书。

这十一夜，说书人讲的，就是这台时光机的故事。时光机的学名，叫 Git。

第一夜

为什么需要时光机

故事线

女巫接了个活：给楼下花店做网站。

一下午，她灵感爆棚，把首页改成了葬礼风——黑底，白字，正中一朵枯萎的玫瑰，凋零得很有艺术感。

老板娘端着茶杯路过，瞥了一眼，茶差点洒了：“姑娘，我卖的是花，不是 sadness。”

女巫僵住了。她想回到今天早上——那时候首页还是粉的，花还是开的，老板娘还是笑的。

可没有时光机。她只能重做，一行一行往回改，改到半夜，边改边哭，哭到玫瑰都看不清了。

时光机，就是 Git——程序员给"后悔药"起的工程名。

我们的例子你正在读的这篇教程，自己就是用 Git 写的：第一版用 11 个 commit 搭起，一夜一张快照。哪天我想翻出第一夜的初稿，git log 找到它，checkout 就行。版本控制不是大道理，是这篇教程的出生证明。
女巫的悄悄话说书人敲醒木：你们知道"git"这个词，本来是什么意思吗？英式俚语里，git 是"笨蛋、讨厌鬼"。发明者 Linus 自己说的："我是个自大狂，我用自己的名字命名所有项目。先是 Linux，现在是 git。"——他骂的是自己。时光机的学名，是发明者的自嘲。
故事角色对照表十一夜所有比喻，一一对应 git 真东西，晕的时候回来查：
时光机 = Git 本体 · 拍照/按快门 = git commit · 照片 = 一个 commit（快照）
取景框 = 暂存区（staging area），git add = 把文件搬进取景框
相册目录 = git log 看到的历史 · 书签 HEAD = 你现在站在哪张照片上
平行宇宙 = 分支（branch）· 云端管理局 = GitHub · 魔法钥匙 = SSH key
📦 教科书 · 第一夜
版本控制（version control）
记录文件每一次变化的系统。每次记录叫一个版本（version），随时可以回到任意一个版本。
✎ 补：快照不占地方——Git 存的是每次的完整快照，但内容相同的文件只存一份，打包时还会再压缩。
✎ 记：关键词两个——“记住每一次变化”“随时回去”。
为什么需要
人会改错、会后悔、会想试新想法又怕弄坏旧的。版本控制就是"后悔药"的工程实现。
✎ 补：版本控制不只给程序员——设计师管作品集，学生管论文，人人用得上。
一句话总结：版本控制 = 给文件拍时间快照（snapshot），改崩了，翻照片回去。
你试试在电脑上建个文件夹，塞三个"网站最终版2""真的最终版"式的文件名——先体会一下没有版本控制的痛，再往下学。
欲知后事如何：时光机到手，第一次开机，它先问了女巫三个问题……
第二夜

开机三件事

故事线

时光机开机，第一句："你谁？报上名来。"

git config --global user.name "女巫"
git config --global user.email "witchj@example.com"

时光机每张照片都要署名。不署名的照片，它不存。认人，是时光机家族的规矩。

然后，造机器：

git init

你走进网站文件夹，运行 git init——等于在里面安装了一台时光机（它叫 .git，藏在文件夹里看不见）。文件夹本来就有，是你的；时光机是装进去的引擎。装完，这个文件夹就升级了，从此叫仓库。

然后，拍照两步走。女巫问："为什么不能直接拍？非要先取景？"

说书人笑了："因为你可以只拍三件衣服中的两件。取景框，在 Git 里叫暂存区（staging area）——就是让你决定，这次存什么。"

第一步，取景。把改过的文件，搬进取景框：

git add .

. 的意思是：全都搬，一个不留。也可以只搬一件：git add index.html。

第二步，按快门：

git commit -m "把首页改成葬礼风"

女巫第一次按快门，忘了喊名字。时光机倒没骂她，"唰"地摊开一本小册子："现想也行，写这儿吧。"

原来 -m 后面的，就是照片的名字。带上 -m，名字直接喊出来；不带，它就打开编辑器等你现写——反正不能没有名字。老手都带 -m，快，还不用等它翻册子。

我们的例子第二夜写完，我是这么存的：git add git-time-machine.md 取景，再 git commit -m "第二夜：开机三件事" 按快门。git log 里多了一行，照片洗出来了，有名字，有署名。名字起得越清楚，未来的你越感谢现在的你。
女巫的悄悄话其实有个懒人咒：git commit -a -m "名字"，取景快门一步到位。但注意：-a 只管已经拍过照的老文件（已跟踪的），新文件还是得先 add，它不认生面孔。新手先练两步走，手感对了再偷懒。先学会走，再学飞。
📦 教科书 · 第二夜
仓库（repository）
被 Git 管理的文件夹。git init 会在里面建一个 .git 目录，从此每次变化都有记录。
工作区（working directory）
你实际改文件的地方，就是文件夹本身。
暂存区（staging area）
工作区和仓库之间的"取景框"。git add 把改动搬进去，你可以只选一部分文件，不必全存。
✎ 记：三个区排排坐——工作区（干活）、暂存区（取景框）、仓库（相册）。add 管前一半，commit 管后一半。
✎ 诀：commit 前先 git diff --cached 验货——取景框里装了啥，拍之前看一眼。
提交（commit）
git commit 把暂存区的内容拍成一张快照，存进仓库。-m 后面跟本次说明（message）：带上它，名字直接喊出来；不带它，git 就打开编辑器等你现写。两种都能存，老手都带 -m，快。
✎ 记：commit 第一行 50 字以内、祈使句（"修 bug"不写"修了 bug"）——log 里才好看。
标准三步
git add（取景）→ git commit -m（快门）→ 快照入库。
一句话总结：add 是取景（进暂存区），commit 是快门，-m 是照片名。三步，一张快照。
你试试亲手走三步：git init → 写个 hello.txt → git add → git commit -m "你好时光机"。再用 git log 找到它。
欲知后事如何：照片越存越多，怎么翻看？……
第三夜

翻相册

故事线

照片存多了，得会翻。女巫学会三招。

第一招，体检：

git status

时光机报告："三件衣服换了，还没拍照；两张照片已存档。"哪些改了没存，一目了然。这是女巫每天念得最多的一句咒，相当于进门先照镜子。

第二招，翻目录：

git log --oneline

相册目录，一行一张照片。哪天拍的、叫什么，全在上面。--oneline 是"说人话版"，不加它，日志啰嗦得像老太太的裹脚布。

第三招，找不同：

git diff

跟玩"找不同"游戏一样。改了哪几个字，哪一行多了个逗号，全给你标出来。

女巫翻开相册，沉默了。昨天一下午，她改的全是错别字。把"的"改成"得"，又改回来。时光机如实记录，一点面子不给。

我们的例子不信？这篇教程自己的相册，翻给你看：
$ git log --pretty=format:"%s" --reverse

📦 教科书 · 第三夜
git status
查看工作区和暂存区的状态。哪些文件被改了、哪些已取景、哪些还没拍照，一次看清。新手每天第一句咒。
✎ 记：git status 会直接告诉你撤销命令——终端机在教你，不用死记硬背。
git log
查看提交历史（谁、何时、拍了什么）。--oneline 把每条记录压成一行，目录式浏览。
✎ 补：git log -- <文件名> 只看这一个文件的历史。
git diff
查看"还没取景的改动"具体改了什么。工作区 vs 暂存区，逐行找不同。
✎ 记：diff 默认比“工作区 vs 暂存区”。想看“暂存区 vs 上次提交”，加 --cached。
三者的分工
status 看现在（照镜子），log 看过去（翻目录），diff 看差别（找不同）。
一句话总结：status 照镜子，log 翻目录，diff 找不同。
你试试把 hello.txt 改一个字，依次跑 git status / git diff / git log，说出三者的分工：状态、差别、历史。
欲知后事如何：翻到三天前的照片，女巫真想回去。那张照片里，网站还是好的……
第四夜

后悔药，兑现

故事线

后悔药，今晚兑现。两种吃法。

轻量版，只还一张照片：

git checkout -- index.html

这一个文件，回到照片里的样子。其他文件，不动。精准打击。注意 -- 后面有个空格，别念错咒，念错不灵。

重量版，整条时间线倒带：

git reset --hard HEAD~1

HEAD~1 就是"书签往前挪一张"。回到上一个快照。按下去之前，时光机抖三抖，弹出红字："倒带之后回不来，你想好了吗？"

女巫的手，悬在半空。

我们的例子假如我把第三夜例子的措辞改坏了，越改越别扭——创可贴上场：git checkout -- git-time-machine.md，这个文件的改动回到上次 commit 的样子，其他十夜毫发无伤。至于 reset --hard？第一版的 11 个 commit，我一个都不想丢，核按钮一次没碰过。创可贴常用，核按钮供着。
女巫的悄悄话reset 其实有三档：--soft、--mixed、--hard，一档比一档狠。记住最狠的那档叫 hard 就够了，其他的等你成了大女巫再说。
📦 教科书 · 第四夜
HEAD
一个指针（pointer，书签），永远指向"你现在站在哪"。HEAD~1 = 上一张快照，HEAD~2 = 上上张。
git checkout -- <文件名>
用仓库里的版本覆盖工作区的文件。只影响这一个文件，其他不动。后悔药轻量版。
✎ 补：新版 Git 更推荐 git restore <文件名>，作用一样，语义更清楚（restore = 还原）。
git reset --hard HEAD~1
把 HEAD 指回上一个提交，同时清空暂存区、覆盖工作区。整条时间线倒带。已经 commit 过的，reflog 里还留着底，能抢救回来；但没 commit 的改动，真没了，神仙难救。
✎ 补：push 出去的错别字别用 reset——git revert 新建一个"反向提交"来 undo，历史不动，最安全。
✎ 记：--hard 是核按钮。没 commit 的改动，真没了——提交是你的安全带。
✎ 记：git commit --amend 改上一次提交（忘加文件/写错字）——但 push 过的别碰。
危险等级
checkout 是创可贴，reset --hard 是核按钮。新手先只用 checkout。
一句话总结：checkout 修一张照片，reset 倒整条时间线。--hard 是核按钮，新手先别碰。
你试试故意写错一行，先用 git checkout -- 创可贴救回来；再故意把 commit 名字写错，用 git commit --amend 改掉它。
欲知后事如何：老板娘又来了："加个夜间模式。但现在的版本别动，客人还在用。"一个身体，怎么同时做两件事？……
第五夜

平行宇宙

故事线

时光机的终极功能：开平行宇宙。分支，就是这么回事。

git branch night-mode

新宇宙诞生，名字叫 night-mode。主宇宙叫 main，原版在里面睡大觉，毫发无伤。

git switch night-mode

跳过去。在新宇宙里熬夜调样式，把配色调成"葬礼风2.0"。主宇宙的老板娘毫不知情，继续卖花。

git branch

不加名字，就是查户口：现在有几个宇宙，前面带 * 的是你正站的那个。

我们的例子假如写第五夜时，我想试试把“平行宇宙”改叫“大胆宇宙”，又怕改完后悔——开个分支：git branch test-rename，跳过去随便改。试完觉得还是“平行宇宙”好，分支一删，主宇宙干干净净。一张小纸条的成本，零心理负担。
女巫的悄悄话分支在时光机里只是一张小纸条（指针），41 个字节，开一万个宇宙也不心疼。所以大胆开，别省 —— 这句话值得再听一遍。
📦 教科书 · 第五夜
分支（branch）
本质是一个轻量指针（小纸条），指向某张快照。开分支 = 写一张新纸条，成本极低。
git branch <名字>
创建新分支（新平行宇宙）。只建不跳。
git switch <名字>
切换到指定分支（跳进那个宇宙）。也可以一步到位：git switch -c night-mode（新建并跳入）。
✎ 记：git branch 新名字 只建不跳——你还站在 main 上，别急着 commit。
main
主分支（主宇宙），默认的大本营。所有宇宙最后都要往这里汇总。
为什么分支这么便宜
因为它只是一张 41 字节的小纸条，不复制文件。所以大胆开，别省。
✎ 记：git branch -d 删分支，有没合并的活它不让删；大写 -D 才是强删。
一句话总结：branch = 平行宇宙，互不干扰。main 是主宇宙，大本营。
你试试开个分支 test-rename，跳过去随便改，改完删掉它。体会一下：一张小纸条的成本，零心理负担。
欲知后事如何：夜间模式调好了，怎么把成果搬回主宇宙？……
第六夜

宇宙合并，与打架

故事线

搬成果，叫合并。先回主宇宙：

git switch main
git merge night-mode

顺利的时候，无声无息，世界和平。新功能直接长在了主宇宙里。

但如果两个宇宙改了同一行——主宇宙把按钮改成红色，night-mode 宇宙把同一行改成蓝色——时光机死机，举白旗："这段你自己定！我选不出来！"

女巫打开文件，看见了打架现场：

<<<<<<< HEAD
<button>红色按钮</button>
=======
<button>蓝色按钮</button>
>>>>>>> night-mode

======= 上面是主宇宙的，下面是平行宇宙的。女巫亲手删掉不要的，留下要的，把那些 <<<<<<< 符号清干净。再存一张快照：

git add .
git commit -m "裁决：按钮用红色"

世界恢复和平。

我们的例子标准的 merge 长这样：分支上改了个错别字，主分支上同一段也动了句话，git merge 时举白旗。打开文件，<<<<<<< 上面是主宇宙，下面是分支，亲手二选一，删干净标记，git add + git commit，世界和平。裁决权在人，不在机器。
女巫的悄悄话快进合并时，时光机的内心独白："这点路，就不劳您费心了，我自己走过去。"——主宇宙没动过，它自己挪下书签就完事。
📦 教科书 · 第六夜
合并（merge）
git merge <分支名>，把指定分支的成果并入当前分支。先 switch 回主宇宙，再 merge。
冲突（conflict）
两个分支改了同一文件的同一行，Git 无法自动判断听谁的，合并暂停，等人裁决。
✎ 记：merge 打到一半想跑？git merge --abort 一键回到合并前。
✎ 记：冲突不是坏了，是 Git 在问“听谁的”。两种改法都留着，等你裁决——代码没丢，别慌。
冲突标记（conflict markers）
<<<<<<< HEAD 到 ======= 之间是当前分支的内容，======= 到 >>>>>>> 分支名 之间是对方的内容。亲手二选一（或融合），删掉所有标记符号。
裁完之后
git add + git commit 再存一张快照，合并才算完成。
快进合并（fast-forward）
如果主宇宙这段时间啥也没干，合并只是"把书签往前挪"，连真正的合并都算不上。
✎ 补：git log --oneline --graph 把分支画成 ASCII 图，合并长啥样一眼看清。
一句话总结：merge = 搬运成果；conflict = 同一行两种改法，机器投降，人来裁决。裁完再存一张快照。
你试试在分支和 main 里各改同一文件的同一行，合并，看冲突标记长什么样，手动裁完再 commit。记住 --abort 随时能跑。
欲知后事如何：女巫想把网站给另一个城市的朋友看。时光机再大，也飞不过去……

第七夜

云端时间管理局

故事线

GitHub，就是云端时间管理局。免费帮你存时间线，还能给朋友看。

先登记地址：

git remote add origin <仓库地址>

origin 只是个昵称，意思是"老家"。你叫它"月球"也行，时光机不挑。但全世界都叫 origin，你还是随大流吧。

然后，上传：

git push -u origin main

远程仓库（remote）
存在云端（GitHub）的仓库。git remote add origin <地址> 给它起个本地昵称叫 origin。
✎ 记：git remote -v 看 origin 到底指向哪——push 前看一眼，别推错家。
推送（push）
git push -u origin main，把本地 main 分支推上云端。-u（--set-upstream）记住对应关系，以后只用 git push。
拉取（pull）

✎ 记：git pull = git fetch（只下载不动文件）+ merge。想先看再合，先 fetch。
克隆（clone）

本地（local）vs 云端（cloud）
本地是你的机器，云端是保险柜。push 上传，pull 下载，clone 整台搬走。

不许拍照名单，与魔法钥匙

故事线

女巫第一次 push，兴高采烈。结果第二天，管理局寄来警告信：

说书人摆摆手："别慌。时光机有个'不许拍照名单'，叫 .gitignore。名单上的东西，git add . 也搬不走。"

.DS_Store
.env

年糕凑过来："把我的毛也加上！我的毛不许拍！"女巫："你的毛已经满世界都是了，来不及了。"

名单生效。再 add 再 commit，垃圾们原地消失，干干净净。

一把钥匙掰成两半：私藏的那半（私钥）谁也不给，交公的那半（公钥）贴到 GitHub 的 Settings → SSH keys。从此 push，碰一下就行。

我们的例子这篇教程的仓库根目录下，躺着一个 .gitignore。里面写着：半成品图（带 -labeled、-diagram 后缀的）不许入库，只有成品图（night-*-wide-v1.png）才配进仓库。名单在前，仓库才干净。发布那天，HTTPS 和 SSH 二选一：钥匙串记住 token，或者配一把 SSH 钥匙——手册推荐前者。

📦 教科书 · 第九夜
.gitignore
放在仓库根目录的"不许拍照名单"。每行写一个规则：node_modules/（整个文件夹）、.DS_Store（单个文件）、*.log（通配符 wildcard，所有 log）、!.keep（! 是例外，这个要拍）。
必备三件套（网站项目）
node_modules/、.DS_Store、.env。.env 里是密码密钥，传上公开仓库等于把家门钥匙贴在布告栏。
注意
名单只对"还没拍过照的"生效。已经 commit 进去的，得先删掉再加名单。
✎ 记：.gitignore 只管“还没拍照的”。已经 commit 的，先 git rm --cached <文件名> 取消跟踪（本地文件还在），再进名单。
✎ 补：.DS_Store 这种每台机器都有的垃圾，配一次全局忽略，不用每个仓库写一遍。
✎ 补：别手写 ignore 规则——github.com/github/gitignore 有官方模板，抄。
SSH
ssh-keygen -t ed25519 -C "邮箱" 生成钥匙对。公钥（.pub 结尾）贴到 GitHub，私钥自己藏好，谁也不给。
HTTPS vs SSH
HTTPS 是 GitHub 官方推荐的方式，配合系统凭据管理器（比如 macOS 的钥匙串）记住 token 后，之后 push 不用每次都输；SSH 则是配一次钥匙、之后免打扰。两种都行，看你顺手。故事里走 SSH，是因为"配一次管终身"听起来很爽。
✎ 补：GitHub 官方推荐 HTTPS + 凭据管理器记 token。新手先走 HTTPS，SSH 是进阶玩具。
一句话总结：.gitignore 是不许拍照名单，SSH 是魔法钥匙。一个管干净，一个管省事。
你试试写个 .gitignore，把 .DS_Store 和 *.log 写进去，再 git status 验证垃圾消失。
